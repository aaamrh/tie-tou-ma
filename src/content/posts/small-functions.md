阅读一个函数时，我首先想知道两件事情：它接收什么，最后产生什么。

如果一个函数同时读取文件、修改数据、计算结果和发送请求，理解它就需要记住许多条件。让每个部分拥有清楚的职责，通常比增加注释更有效。

## 从一个计算开始

下面的函数接收一组价格，产生它们的总和。它不读取文件，也不修改传入的数组。

```typescript
function totalPrice(prices: readonly number[]): number {
  for (const price of prices) {
    if (!Number.isFinite(price) || price < 0) {
      throw new RangeError('价格必须是非负的有限数值');
    }
  }

  return prices.reduce((total, price) => total + price, 0);
}

const total = totalPrice([12, 18, 30]);
console.log(total); // 60
```

输入有效时得到结果，输入无效时立即报告错误。调用方不需要猜测返回值是否可靠。

## 计算与操作

计算负责根据输入产生结果。操作负责读取文件、访问网络、保存数据等外部交互。

| 部分 | 接收 | 产生 |
| --- | --- | --- |
| 读取 | 文件路径 | 价格数组 |
| 计算 | 价格数组 | 总价 |
| 保存 | 总价与目标路径 | 写入结果 |

这样的组织方式让变化有明确的位置。修改文件格式时，主要检查读取部分；修改计算规则时，主要检查计算部分。

## 清楚比简短更有用

函数并不是越短越好。判断标准是：阅读者能否清楚地说出它的职责，调用方能否根据输入预测结果。

一个清楚的名称，一组明确的输入，一个能够验证的结果，往往已经足够。
